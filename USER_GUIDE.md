## 1. Назначение платформы

Assistant Flow — мультимодальная AI-платформа:

- корпоративная база знаний и RAG;
- текстовый диалог в Telegram;
- голос (STT/TTS), если включено;
- генерация изображений;
- **OCR / Vision** — текст с фотографий;
- административная консоль для оператора.

---

## 2. Основные интерфейсы

| Интерфейс | Кто использует | Назначение |
|-----------|----------------|------------|
| **Telegram** | Конечный пользователь | Вопросы, RAG, фото, голос, картинки |
| **Admin UI** (`http://localhost:8080` в portfolio) | Оператор | Диагностика, документы, память, оценка RAG |

Административная консоль — **React** (`frontend/admin-ui`), не Streamlit.

---

## 3. Telegram: команды и режимы

| Команда | Действие |
|---------|----------|
| `/start` | Приветствие |
| `/help` | Справка по режимам |
| `/mode text` | Обычный диалог и генерация изображений |
| `/mode rag` | Вопросы по проиндексированной базе знаний |
| `/mode ocr` | Распознавание текста на изображениях |
| `/stats` | Статистика индекса (режим RAG) |
| `/reset` | Сброс режима и in-memory истории RAG |
| `/clear` | Очистка истории (см. `/help`) |

---

## 4. Текстовый режим (`/mode text`)

- Короткие и развёрнутые вопросы на естественном языке.
- Запросы на **генерацию изображений** по описанию (ключевые формулировки вроде «нарисуй…»).
- Память диалога учитывается при ответах, если включена PostgreSQL-память.

**Пример:** «объясни простыми словами, что такое фотосинтез».

---

## 5. RAG (`/mode rag`)

1. Оператор загружает и индексирует документы (Admin UI → **Документы**).
2. Пользователь задаёт вопрос по содержимому базы.
3. Система находит чанки, формирует ответ со ссылками на источники.
4. Оператор смотрит диагностику в **RAG** и **Логи**.

**Пример:** «дай полную сводку по компании NovaTex» (если документы про NovaTex проиндексированы).

Без индексации ответ может уйти в fallback без релевантных источников.

---

## 6. Распознавание текста (OCR)

OCR реализован через **OpenAI Vision** (`chat.completions` с изображением). Локальный Tesseract не используется. Нужны `OPENAI_API_KEY` и модель с поддержкой vision (см. `.env.example`).

### Как запустить OCR

**Вариант A — режим OCR**

1. Отправьте `/mode ocr`.
2. Пришлите **фото** или **файл-изображение** (документ с картинкой).
3. Подпись необязательна: по умолчанию модель извлекает весь видимый текст.

**Вариант B — подпись к фото в `text` / `rag`**

Отправьте изображение с подписью, где явно просят прочитать текст, например:

- «распознай текст»;
- «OCR»;
- «извлеки текст»;
- «прочитай изображение»;
- «текст с картинки».

Если подписи с такими маркерами нет, бот подскажет включить `/mode ocr` — **RAG по картинке без OCR не выполняется**.

### Поведение системы

- Один запрос → один ответ с блоком **«Распознанный текст:»**.
- В `/mode ocr` подпись **дополняет** задание для vision-модели (например: «объясни простыми словами, что написано»). Это по-прежнему **один** вызов Vision, а не цепочка «OCR → отдельный текстовый ассистент».
- События обработки видны оператору в консоли (**Текст** / **Логи**, маршрут `vision_ocr`).

### Пример 1 — фото документа

Пользователь в `/mode ocr` фотографирует:

- страницу договора;
- инструкцию;
- экран с печатным текстом.

**Результат:** текстовое содержимое в ответе Telegram.

### Пример 2 — фото с уточняющей подписью

1. `/mode ocr`.
2. Фото договора с подписью: *«Объясни простыми словами, что написано на изображении»*.
3. Vision-модель получает и стандартный OCR-запрос, и пожелание пользователя — ответ может быть не только «сырым» текстом, но и кратким объяснением содержания.

Для обычного диалога **без** OCR отправляйте текст отдельным сообщением после распознавания или переключитесь в `/mode text`.

### Ограничения OCR

- Качество зависит от освещения, резкости и контраста.
- Ненадёжно: сильное размытие, рукопись, очень мелкий шрифт, плотные таблицы и нестандартная вёрстка.
- Лимиты размера файла и API провайдера — см. сообщения об ошибках в боте.
- OCR **не** подмешивает результат в RAG-automatically; поиск по базе знаний — отдельный режим `/mode rag` по текстовому вопросу.

## 7. Голосовые сценарии

При `AUDIO_ENABLED=true` и настроенных `STT_PROVIDER` / `TTS_PROVIDER`:

- голосовое сообщение → распознавание → ответ текстом или озвучкой;
- диагностика в Admin UI → **Аудио**.

По умолчанию в `.env.example` аудио **отключено** (`disabled`).

---

## 8. Генерация изображений

В `/mode text` опишите желаемую картинку, например: *«нарисуй слона в посудной лавке»*.

Результат — изображение в чате; оператор видит телеметрию в **Изображения**.

---

## 9. Память диалога

- Платформа хранит историю переписки (PostgreSQL при `DATABASE_URL`).
- Пользователь может продолжать тему без повторения контекста.
- Размер контекста для модели **ограничен** — старые реплики могут не попадать в следующий ответ.
- Оператор открывает **Memory** (`/memory`) в консоли: сессии, реплики, влияние на ответ.

Команда `/reset` сбрасывает режим и in-memory буфер RAG; полная очистка PG-сессий — через операторские процедуры (см. RUNBOOK).

## 10. Работа с документами (оператор)

Через Admin UI → **Документы**:

1. загрузка PDF / TXT / MD;
2. preprocessing и индексация;
3. просмотр версий, `chunk_count`, reindex при сбое.

Подробности: [docs/ADMIN_INDEXING.md](docs/ADMIN_INDEXING.md).

## 11. Административная консоль

Разделы (боковое меню):

| Раздел | Путь |
|--------|------|
| Обзор | `/` |
| Сводка | `/summary` |
| Текст | `/text` |
| RAG | `/rag` |
| Изображения | `/images` |
| Аудио | `/audio` |
| Документы | `/documents` |
| Retrieval Settings | `/retrieval` |
| Логи | `/logs` |
| Memory | `/memory` |
| Анализ RAG | `/evaluation` |

Используется для состояния платформы, логов, RAG-диагностики (в т.ч. кэш OFF/MISS/HIT), памяти и оценки качества.
