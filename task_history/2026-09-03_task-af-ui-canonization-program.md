## Порядок и время (~15–20 ч)

1. **Токен-карта + тема день/ночь** (~3–4 ч) — первой: всё остальное строится
   на токенах, иначе страницы красим дважды. Ревизия сырых hex в globals.css →
   токен-карта в духе RF (светлая `:root` = белая земля + голубые панели,
   dark override), hook `useTheme` (localStorage `ai-theme`), toggle в footer
   сайдбара. **КТ-1** (короткий отчёт).
2. **Демо-стандарт: кнопки + бейдж** (~1.5–2 ч) — чип роли 🎭 в сайдбаре
   (отдельно от email), кнопка демо-входа по канону, «↩ К проекту» в footer
   (opener-контракт). **КТ-2.**
3. **Меню-канон + эмодзи-SOT + «Обозначения»** (~4–5 ч) — группы с
   заголовками; карта эмодзи (одна на понятие, в фильтрах и легенде);
   тихие чипы вместо `.status-badge`; экран «Обозначения» по полному канону
   (сетка 3 колонки, панели по смыслу: сессии/кэш/статусы/маршруты,
   `?`-хэлп-поповеры «где используется»). **КТ-3.**
4. **Операционный канон, pairwise-прогон** (~7–10 ч) — карта свойств канона
   (методика LQ Дополнения 6), затем постранично:
   - ядро: Текст, RAG, Изображения, Аудио, Документы — **КТ-4**;
   - остаток: Обзор, Сводка, Retrieval Settings, Memory, Анализ RAG (RAGAS),
     Аудит (RF AuditWorkspace), Логи (**только визуал**: шрифты, пагинация,
     эмодзи/чипы; наполнение не трогать) — **КТ-5**.
5. **Финал** (~1 ч) — headless DOM e2e (обе темы, 375/1280 без переполнения,
   0 JS-ошибок), деплой admin-ui, отчёт. Визуальная приёмка — за владельцем.

- `globals.css`: `:root` заменён на полную токен-карту (dark, дефолт,

  (формула владельца: bg→белый, графит→серо-голубой `#e7ebf3`, hover темнее

  --row-hover-strong`, `--tooltip-*`, `--shadow(-lg)`, сигнальные тексты/тинты

  --critical` × `-text/-soft-bg/-soft-border`), stage-цвета, градиент акцента.
- Токенизация сырых значений (sed по карте, токен-блок не тронут): ~60

  заливки, чип, modal-close hover); 1 white-alpha border → `var(--border)`.
  Осознанно оставлены сырыми: `#fff` на синих кнопках (градиент/акцент
  сохраняются в обеих темах), тёмные border-цвета cache/severity (читаемы на
  белом), fallback `var(--error, #c0392b)`, box-shadow-флёр.

### Пост-финальный фикс: превью OCR-входа в «Тексте» (старый режим аутентификации)

**Симптом (владелец):** при входе в «Текст» браузер показывает нативную
форму запроса пароля; после отказа превью файлов OCR не грузится.
Вчера то же было в «Изображениях» — там уже исправлено.

**Root cause:** `TextPage` рендерил превью OCR-входа сырым
`<img src="/api/assets/preview?...">` — запрос без Bearer-токена; API
отвечает 401 с `WWW-Authenticate: Basic`, что открывает нативный
пароль-диалог браузера. Именно на этот грабль документирован хук
`useAuthedAssetUrl` (авторизованный blob-фетч), применённый в
Изображениях/Аудио.

**Фикс:** `TextPage` переведён на `useAuthedAssetUrl` (как в
Изображениях): загрузка blob'ом с Bearer, fallback-панель «Не удалось
загрузить превью изображения OCR» при отказе API. Удалён ставший
мёртвым хелпер `getAssetPreviewUrl` из `api/client.ts`.

**E2e** `af-e2e-asset-auth.js` (новый, в `e2e/`): Текст/Изображения/

### Шаг 6, исправление: базовый размер шрифта (жалоба владельца)
