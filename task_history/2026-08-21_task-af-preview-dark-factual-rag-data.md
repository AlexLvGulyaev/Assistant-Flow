# 3. Что означает `faithfulness = 0.9` в AF

## 3.1 Откуда берётся метрика

- AF использует библиотеку **RAGAS** для оценки качества RAG.
- Метрика `faithfulness` вычисляется классом `ragas.metrics.Faithfulness` (или legacy alias `faithfulness`) через вызов LLM `gpt-4o-mini` (модель задаётся env `RAGAS_CHAT_MODEL`, по умолчанию `gpt-4o-mini`).
- Источник кода: `services/evaluation/ragas_adapter.py`, функции `try_run_ragas_metrics` / `run_ragas_evaluation`, `RAGAS_METRIC_KEYS` включает `ragas.faithfulness`.

## 3.2 Что именно измеряет

- `faithfulness` (RAGAS) измеряет, **насколько сгенерированный ответ опирается на предоставленные retrieved contexts**, то есть насколько факты из ответа можно подтвердить по найденным чанкам.
- Это **не** точность ответа вообще и **не** сходство вопроса и ответа.
- Значение `0.9` означает: примерно 90% утверждений в ответе можно обосновать retrieved contexts.

## 3.3 Корректное короткое русское название для preview

- **Лучший вариант:** «Соответствие ответа источникам».
- **Допустимые альтернативы:** «Верность контексту», «Faithfulness» (оставить как есть, если нужен технический термин).
- **Не рекомендуется:** «Точность», «Достоверность», «Релевантность» — эти слова искажают смысл метрики.

# 4. Можно ли безопасно показывать scores `0.46 / 0.63 / 0.65` как relevance score

## 4.1 Да, scores относятся именно к этому execution

- `processing_logs` для execution `a4f7dbd2-...` содержит массив `scores`: `[0.46454524993896484, 0.6292791366577148, 0.6485806107521057]`.
- Каждому score соответствует chunk в `retrieved_chunks` с тем же значением и source/filename/text_fp.
- Все три chunks отфильтрованы security-ролью `employee` и использованы в RAG (`used_chunks_count: 3`).

## 4.2 Но это не классический «relevance score»

- В Weaviate backend score — это **vector distance** (cosine distance / L2-подобная метрика), а не probability-релевантность от 0 до 1.
- В контракте `RetrievalSearchResult` прямо указано: `score` — backend-local семантика, не сравнима между разными backend без нормализации.
- Поэтому на preview корректнее называть их:
  - **«retrieval score»** (нейтрально),
  - **«оценка близости»**,
  - **«distance / score»**,
  - или просто **«score»** с осью «меньше = ближе» (для Weaviate/Chroma distance).
- Название **«relevance score» / «оценка релевантности»** допустимо только если явно не подразумевается шкала 0–1 «вероятность релевантности». Для этого execution в контексте Weaviate это **distance-like значения**, где меньшее число означает более близкий чанк.

## 4.3 Рекомендация для preview

- Показывать как **`retrieval score`** или **`оценка близости`**.
- Если нужна более понятная для не-технической аудитории формулировка — **`score`** без дополнительной интерпретации.
- **Не писать:** «вероятность релевантности 46%» или «релевантность 0.46 из 1».
