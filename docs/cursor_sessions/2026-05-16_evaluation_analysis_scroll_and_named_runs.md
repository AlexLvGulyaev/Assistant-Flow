# Промпт для Cursor: доработка scroll UX и именования наборов в «Анализе качества RAG»

```text
Используй Codex 5.3.

Прочитай и выполни. Общаемся и пишем комментарии/отчеты строго на русском языке.

Нужно доработать экран «Анализ» в разделе «Анализ качества RAG» Admin UI Assistant Flow.

Контекст:
Предыдущими проходами уже выполнены:
- русификация списка RAG-сессий;
- переименование раздела в «Анализ качества RAG»;
- переименование вкладки run-ов в «Анализ»;
- компактная верхняя панель выбранного набора;
- блок `Run` переименован в «Параметры запуска»;
- из «Параметров запуска» убран backend;
- удален блок Source со списком execution_id.

Теперь нужно доработать два следующих UX-узких места:
1. неудобный вложенный скроллинг на экране анализа;
2. отсутствие пользовательского имени набора анализа.

ВАЖНО:
- язык интерфейса — русский;
- новые session logs / отчеты — только на русском;
- технические идентификаторы не переводить:
  - RAG
  - RAGAS
  - top_k
  - fallback
  - execution_id
  - Weaviate / Chroma / FAISS
- execution_id не переименовывать и не скрывать там, где он нужен для диагностики конкретной RAG-сессии.

==================================================
ЦЕЛЬ
==================================================

Сделать экран «Анализ» более удобным для оператора:

- убрать ощущение scroll hell;
- сделать поведение прокрутки предсказуемым;
- дать пользователю возможность задавать понятное имя набора анализа;
- сохранить compact operational style;
- не ломать текущий RAGAS / retrieval workflow.

==================================================
ЧАСТЬ 1. SCROLL UX
==================================================

Проблема:
На экране анализа сейчас слишком много вложенных областей прокрутки:
- список наборов слева;
- список RAG-сессий внутри выбранного набора;
- правая forensic-панель выбранной сессии;
- retrieval chunks внутри панели.

Из-за этого колесо мыши ведет себя неочевидно, часть экрана «залипает», а пользователь теряет контекст.

Нужно:
1. Проанализировать текущую структуру scroll containers в `EvaluationPage.tsx` и связанных CSS.
2. Сократить количество независимых внутренних скроллов.
3. Сохранить отдельный скролл для левой навигации по наборам, если он уже нужен.
4. Для основной рабочей области сделать максимально предсказуемую модель:
   - верхняя панель параметров/summary остается компактной;
   - список RAG-сессий и выбранная forensic-панель не должны конфликтовать по прокрутке;
   - retrieval chunks не должны создавать отдельный агрессивный scroll hell, если это можно безопасно избежать.
5. Не превращать экран в одну бесконечную «простыню», но убрать лишние вложенные scroll области.

Ожидаемый результат:
- колесо мыши работает ожидаемо;
- верхняя панель не съедает много высоты;
- выбранная RAG-сессия читается без борьбы с несколькими scrollbars;
- экран выглядит как единая operational-консоль.

==================================================
ЧАСТЬ 2. ИМЯ НАБОРА АНАЛИЗА
==================================================

Проблема:
Сейчас набор анализа отображается техническим именем вроде:
- `ui-10-turns`
- `interactive-import-...`

Пользователю нужно иметь возможность задавать понятное имя набора, например:
- `Weaviate c1000 k5 baseline`
- `Weaviate c1000 k3`
- `Chunk 300 overlap 50`
- `Negative-answer кейсы`

Нужно:
1. Найти текущую модель создания/import evaluation run.
2. Проверить, есть ли уже поле run name / dataset name / title, которое можно использовать без изменения схемы.
3. Если существующего поля достаточно — использовать его.
4. Если без backend-изменения невозможно — сначала предложить минимальный безопасный вариант и НЕ делать schema migration без явного подтверждения оператора.
5. На UI добавить поле имени набора при импорте/создании набора, если это возможно в текущем API.
6. В списке наборов и в заголовке карточки показывать человекочитаемое имя.
7. Если имя не задано — оставить текущий fallback на техническое имя.

ВАЖНО:
Не делать широкую переделку evaluation schema.
Если требуется backend change, он должен быть минимальным и явно описан в session log.

==================================================
НЕ ТРОГАТЬ
==================================================

Не менять:

- retrieval pipeline;

- evaluation metric semantics;
```
