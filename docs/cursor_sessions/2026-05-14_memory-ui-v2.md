# Memory / Sessions UI v2 — operational observability (2026-05-14)

## Prompt (abridged)

Привести Memory / Sessions UI к единому стилю Assistant Flow Admin Console: эволюция, не новый продукт; не ломать backend и memory pipeline; использовать существующие API.

Требования:

1. Session summary → компактные карточки (PG memory, runtime source, budget, активные сессии, avg turns, clear/reset, trimmed).
2. Conversation preview → bubbles (👤 / 🤖), последние 3–6 turn, скролл, не полный чат.
3. Lifecycle `memory_*` → timeline (время, latency, loaded, trimmed).
4. Runtime context card: loaded PG, after trim, sent to LLM, RAG yes/no, Meta yes/no, budget X/Y.
5. UI-only фильтр «скрыть synthetic / test» (tg отрицательные smoke, 9e12…9.99e12, hello smoke / LIM-* в превью).
6. Inspect: убрать шум из основного слоя → `Advanced diagnostics` (UUID, raw JSON).
7. Тёмная тема, карточки, компактность, без «простыней».

Проверка: Memory → RAG сессия → smoke → фильтр → timeline → runtime card. Commit не выполнять.

### Backend

Не менялся. Данные: `GET /api/memory/observability/summary`, `GET /api/memory/sessions`, `GET /api/memory/sessions/{id}`.

### Эвристики (только UI)

- **Trimmed (выборка):** число строк в текущем списке (до 80), где `messages_count > max_llm_messages` из summary — оценка, не глобальная метрика БД.
- **RAG / Meta** в runtime card: по полю `details.route` и префиксу stage `memory_meta*` в событиях lifecycle для этой сессии.
- **Synthetic:** отрицательный `telegram_user_id` &lt; −9×10¹⁴; положительный 9×10¹²…9.999×10¹² (smoke v1); в детале — превью с `hello smoke`, `world smoke`, `LIM-*`, `ORD-*`.
