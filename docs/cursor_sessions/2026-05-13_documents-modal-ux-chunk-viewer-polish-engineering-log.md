# Engineering log: Documents — polish UX модалок чанка и просмотра документа (2026-05-13)

## Контекст

После предыдущего прохода параметры чанка стали двухколоночными, но при ручной проверке остались проблемы: **слишком плотная сетка**, **ALL CAPS-подписи**, **«прыгающее» окно** в зависимости от длины текста чанка; у просмотра RAW/canonical/edit не хватало **стабильной высоты** для редактирования; на панели предпросмотра дублировалась точка входа в редактирование.

## Root cause плохой читаемости (chunk details)

1. **Визуальная плотность:** мелкий шрифт, узкий `column-gap`, узкий зазор label/value в паре — длинные UUID визуально «давили» на короткие поля в той же колонке.
2. **Подписи:** `text-transform: uppercase` + мелкий `letter-spacing` ухудшали сканирование глазом по сравнению с остальными панелями Documents.
3. **Раскладка:** идентификаторы стояли в одной колонке с «человеческими» полями — взгляд сразу цеплялся за длинные строки.
4. **Размер модалки:** высота/внутренний layout зависели от объёма контента: основной блок текста не был жёстко ограничен во **flex-колонке** с `min-height: 0`, из-за чего окно вело себя нестабильно при переключении между чанками.

## Выбранная раскладка параметров чанка

- **Левая колонка (читаемое):** Источник, **Версия** только как `v{N}` (если есть номер), № чанка, Backend, Коллекция, Модель, Размер, Создан.
- **Правая колонка (id и длинные тех. значения):** Документ (id), Версия (id), Строка чанка (id), Вектор (id); дополнительно строки из `metadata` — только **длинные** строковые/числовые значения (≥ 24 символов), не совпадающие с уже показанными id (чтобы не дублировать).

Подписи — **русские**, без верхнего регистра для всей строки; «Backend» оставлен латиницей по продуктовому смыслу.

## Фиксированный размер модалок (Documents)

Для **`rag-chunk-modal--document`** и **`rag-chunk-modal--chunk-detail`** задан единый каркас:

- `width: clamp(300px, 72vw, 920px)`
- `height` / `max-height: clamp(480px, 72vh, 720px)`

Контент между шапкой и футером обёрнут в **`rag-chunk-modal__main--docs`**: колонка flex с `min-height: 0`, прокручиваются **`rag-chunk-modal__body--docs-fill`** и **`textarea`** внутри main, а не «растягивается» всё окно.

Базовый **`.rag-chunk-modal`** (RAG / Text / Audio / Images) **не менялся** — отдельные модификаторы только у Documents.

## Редактирование canonical текста

**Причина переноса точки входа:** одна явная дорожка «просмотр → редактирование» снижает путаницу и дублирование с предпросмотром панели.

- С панели **«Предпросмотр»** убрана ссылка **«редактировать»**; остаётся **«открыть документ»** (canonical viewer).
- Кнопка **«Редактировать»** остаётся в шапке модалки **indexed (canonical) viewer**; сохранение и reindex **без изменений логики**.

## Ручная проверка (чеклист)

1. Documents → **детали чанка:** русские подписи, слева короткие поля, справа id; окно **одинаковой** габаритной высоты при разных чанках; текст чанка **скроллится** внутри.
2. Documents → **открыть RAW:** тот же каркас окна, скролл текста.
3. Documents → **открыть документ:** тот же каркас; кнопка **«Редактировать»** в шапке viewer.
4. Предпросмотр: только **«открыть документ»**, без отдельного «редактировать».
5. Редактирование: из viewer → edit → **Сохранить как новую версию** → убедиться, что сценарий и подсказки reindex прежние.
6. RAG → модалка чанка: размер и поведение **как раньше** (без классов `--document` / `--chunk-detail`).

## Пересборка и деплой

| Вопрос | Ответ |
|--------|--------|
| **Нужна ли пересборка?** | Да, изменён только **React admin-ui** (статика). Backend / бот / API **не трогались**. |
| **Какие сервисы пересобирать?** | В стеке **portfolio** — образ **`admin-ui`**. Streamlit **`assistant-admin`** из `docker-compose.assistant.yml` этот Vite-UI **не содержит**. |
| **Полная команда docker compose** | Из корня репозитория (после правок в `frontend/admin-ui`): `docker compose -f docker-compose.portfolio.yml build --no-cache admin-ui && docker compose -f docker-compose.portfolio.yml up -d admin-ui` |
| **Нужен ли отдельный frontend build?** | Для **локальной** проверки: `cd frontend/admin-ui && npm run build` (или `npm run dev`). В Docker образ **admin-ui** сборка Vite выполняется **внутри Dockerfile** при `build`. |
| **Reindex / restart / кэш?** | **Reindex не требуется** (только UI). Достаточно пересобрать/перезапустить контейнер **admin-ui** или обновить статику CDN/nginx. Кэш браузера: при «старом» бандле — жёсткое обновление или инкогнито; при необходимости очистить кэш Vite dev (`.vite`). |
