# 💼 Assistant Flow — бизнес-ценность

**Статус:** актуально на 2026-09-15.

---

## Бизнес-проблема

Во многих компаниях знания существуют, но ими сложно пользоваться.

| Симптом | Чем оборачивается |
|---------|-------------------|
| Регламенты и инструкции лежат в PDF и папках | сотрудник ищет вручную или не ищет вовсе; поддержка отвечает на одни и те же вопросы |
| Инструкции быстро устаревают | ответы расходятся с фактической практикой |
| Новые сотрудники долго входят в процессы | недели вместо дней на разбор внутренних документов |
| AI-боты работают как «чёрный ящик» | невозможно понять, почему получен тот или иной ответ; доверие к автоматизации не растёт |
| Нет контура эксплуатации AI | ответ есть, а диагностики, качества и аудита — нет; инцидент разбирается вслепую |

---

## Решение

**Assistant Flow** — единая AI-платформа, которая объединяет:

- **AI-ассистента в Telegram** — текст, RAG, OCR/Vision, голос (STT/TTS), генерация изображений: один ассистент вместо набора узких ботов.
- **Управляемую базу знаний** — не «файлы на диске», а документы с версиями, lifecycle и индексацией; поиск по корпоративным источникам (RAG) с блоком «Источники» в ответе.
- **Переключаемые vector-бэкенды** (Chroma / FAISS / Weaviate) — инфраструктура поиска развивается без смены кода.
- **Операционную консоль** — состояние платформы, все AI-сессии по модальностям, трассировка этапов, память диалога, журнал аудита.
- **Контроль качества** — RAGAS-метрики и ручная валидация: качество RAG измеряется, а не оценивается «на глаз».
- **Несколько AI-провайдеров** (OpenAI / GigaChat / Proxy API) — гибкость выбора и стоимость на телеметрии.

Позиционирование: платформа ориентирована не только на генерацию ответов, но и на полноценную эксплуатацию AI-систем — с диагностикой, трассировкой, наблюдаемостью поиска и журналом аудита.

---

## Эффект

| Что даёт | Как это видно |
|----------|---------------|
| Знания доступны ассистенту | RAG-ответ на основе проиндексированных документов с указанием источников |
| Обработка прозрачна | трассировка каждой сессии: этапы pipeline, телеметрия провайдеров, найденные чанки с score и latency |
| Качество измеримо | RAGAS (faithfulness, relevance), ручная валидация, сравнение сессий в evaluation run |
| Доступ контролируем | Bearer-токен, RBAC, демо-вход read-only, журнал аудита обращений к Admin API |
| Поиск управляем | версии документов, lifecycle, retrieval security по visibility, retrieval cache (OFF/MISS/HIT) |
| Система сопровождаема | healthchecks, graceful degradation, журнал аудита, воспроизводимое развёртывание по DEPLOYMENT_GUIDE |

---

## Выгода

- **Для владельцев знаний:** регламенты и инструкции становятся отвечаемыми через ассистента — с контролем того, какие документы участвуют в поиске.
- **Службам поддержки:** типовые вопросы уходят в ассистента, операторы видят трассировку и качество ответов.
- **Инженерам эксплуатации:** диагностика AI-контуров, latency, cache-состояния и аудит — в одном интерфейсе, а не в разрозненных логах.
- **Организациям в целом:** автоматизация с проверяемой цепочкой «запрос → источник → ответ», а не «чёрный ящик».

---

## Честные границы

- **Исследовательская платформа (MVP)**: seed-документы — учебный материал для демонстрации, а не корпоративная база знаний.
- **Single-tenant**: нет multi-tenant изоляции и внешнего IAM/OAuth-провайдера аутентификации.
- **Heavy RAG на малых VPS**: reindex при конкурентных RAG-запросах может деградировать при 8 GiB RAM.
- Перед production требуется: корпоративная аутентификация, CI/CD, мониторинг, бэкапы.
