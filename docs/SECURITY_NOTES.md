# Заметки по безопасности (черновик)

Документ фиксирует **известные ограничения** portfolio-прототипа. Не заменяет полноценный threat model и не является исчерпывающим чек-листом для продакшена.

## Admin API

- Маршруты под префиксом `/api` **не защищены** встроенной аутентификацией или RBAC.
- Любой, кто может достучаться до сервиса по сети, может вызывать чтение логов, обзор состояния, загрузку документов и reindex — в объёме, реализованном кодом.
- **Не публикуйте** Admin API в открытый интернет без:
  - reverse proxy (например, nginx, Traefik) с TLS;
  - вашей модели доступа (VPN, mTLS, OAuth2 proxy, IP allowlist и т.д.);
  - ограничения rate limit / размера тел по политике.

## Single-tenant прототип

- Проект рассчитан на демонстрацию архитектуры и операций, а не на мультитенантный SaaS с изоляцией данных между клиентами.

## Секреты

- Ключи Telegram, LLM, ProxyAPI и строки подключения к БД задаются только через **переменные окружения**.
- Файлы `.env` / `.env.server` **не должны** попадать в git (см. `.gitignore`).
- Перед публичной публикацией репозитория выполните проверку истории и рабочей копии на утечки (см. [GITHUB_PREP.md](GITHUB_PREP.md)).

## CORS

- Разрешённые origins для Admin API задаются через `ADMIN_API_CORS_ORIGINS` и дефолты в коде. Для продакшена список нужно **сузить** под реальные домены UI.

## Данные и ассеты

- Через API доступны превью определённых типов ассетов. Политика хранения и удаления чувствительных файлов — на стороне оператора.

## Chroma и PostgreSQL

- Доступ к Chroma и Postgres в демо-compose привязан к сети Docker и портам на хосте. В публичной среде ограничьте exposure (firewall, bind address).
