# 🧭 Маршрут проверки демо — Assistant Flow

Короткий маршрут проверки живого демо: два контура — пользовательский (Telegram-бот)
и операционный (Admin UI, read-only демо-вход).

## Точка входа

- **Telegram-бот:** бот оператора (имя задаётся в BotFather при развёртывании — [DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md) §4; общего demo-бота в репозитории нет). `/start`.
- **Admin UI:** `http://localhost:8080` (локально) или витрина `https://af-admin.alex-n8n.site`. Вход — **«Войти в демо-режиме»** (read-only, без админ-токена).

## Маршрут (2–5 действий)

1. **Telegram → /start** → бот отвечает приветствием.
2. **/mode text** → вопрос («объясни простыми словами, что такое инфляция») → текстовый ответ в чате.
3. **/mode rag** → вопрос по загруженной базе знаний → ответ + блок **Источники** (файл, score).
4. **Фото + подпись «распознай текст»** → блок «Распознанный текст: …» (OpenAI Vision).
5. **Admin UI → Обзор** → health сервисов, активные AI-провайдеры и retrieval backend; в **RAG** — найденные чанки, latency, состояние retrieval cache (OFF/MISS/HIT).

## Наблюдаемый результат

- Бот отвечает во всех режимах (`processing_logs` фиксирует стадии).
- В консоли видна трассировка каждой сессии: этапы pipeline, телеметрия провайдеров, диагностика retrieval.
- Демо-режим ограничен чтением: операции записи (upload, reindex, настройки) недоступны (403) — полный доступ только с админ-токеном.
