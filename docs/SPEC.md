# 🎯 SPEC — Assistant Flow

> **Ретроспективная спецификация** (2026-09-03): составлена по фактически реализованной системе в соответствии с правилами APL (разработка началась до формализации SPEC; документ фиксирует достигнутый продуктовый контур). Технический план реализации — [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).

---

## 1. Проблема и идея

Знания в компаниях существуют, но ими сложно пользоваться: регламенты в PDF и папках, инструкции устаревают, поддержка отвечает на одни и те же вопросы, AI-боты работают как «чёрный ящик».

**Идея:** единая мультимодальная AI-платформа — Telegram-ассистент + корпоративная база знаний (RAG) + операционная консоль для эксплуатации AI-системы (диагностика, наблюдаемость, качество, безопасность), а не набор одноразовых сценариев.

---

## 2. Целевая аудитория

| Роль | Что делает |
|------|-----------|
| **Пользователь** (сотрудник компании) | Задаёт вопросы в Telegram: текст, RAG по базе знаний, фото (OCR), голос, генерация изображений |
| **Оператор** | Управляет базой знаний, наблюдает и диагностирует сессии в консоли, оценивает качество RAG |
| **Администратор / владелец** | Управляет доступом (токены, роли), видит журнал аудита, эксплуатирует стек через Docker Compose |

## 3. Функциональные требования (реализовано)

### 3.1 Telegram-ассистент
- Режимы: `/mode text` (диалог + генерация изображений), `/mode rag`, `/mode ocr`; `/start`, `/help`, `/stats`, `/reset`, `/clear`.
- Голос: STT/TTS при включении в окружении (`AUDIO_ENABLED`, провайдеры по умолчанию `disabled`); явные таймауты/ретраи OpenAI-клиентов (`AUDIO_TIMEOUT_SECONDS`, `AUDIO_MAX_RETRIES`), оценочная стоимость STT/TTS в telemetry (`cost_usd`, `cost_basis=estimated`).
- Память диалога в PostgreSQL с ограничением размера контекста.

### 3.2 Корпоративная база знаний (RAG)
- Загрузка документов в консоли (лимит `ADMIN_UPLOAD_MAX_MB`, default 25 МБ), версионность документов, предобработка, чанкинг, индексация, переиндексация.
- Поиск по переключаемым векторным бэкендам: **Chroma / FAISS / Weaviate** (выбор в Retrieval Settings, сохраняется в `platform_settings`).
- Опциональный retrieval cache (OFF/MISS/HIT виден в UI), фолбэк-поведение при недоступности хранилища.
- Ответ с блоком «Источники».

### 3.3 Операционная консоль (Admin API + React Admin UI)
- Разделы: Обзор, Сводка, Текст, RAG, Изображения, Аудио, Документы, Retrieval Settings, Логи, Memory, Анализ RAG (RAGAS), Аудит; экраны входа/выхода.
- Трассировка pipeline каждой сессии, диагностика retrieval (чанки, relevance-score, latency, полный текст чанка), token economy за окно (токены + оценочная стоимость per stage/model и grand total).
- Журнал аудита обращений к Admin API.
- Фоновые задачи reindex: очередь `async_jobs` + воркер-поток в admin-api (панель «Фоновые задачи» в Документах).

### 3.4 Доступ и безопасность
- Демо-стандарт APL: `AF_ADMIN_TOKEN` (admin) / `AF_ADMIN_DEMO_TOKEN` (демо, read-only, запечён в UI при сборке); без токенов — локальный режим.
- RBAC-права на Admin API (P9.4), журнал аудита (P9.5), identity foundation (P9.1).
- Data-path security (P8): роли retrieval (guest/employee/admin), visibility документов, санитизация логов (PII masking).

### 3.5 Наблюдаемость и эксплуатация
- Healthchecks (Docker healthcheck admin-api, probes postgres/chroma/weaviate), graceful degradation.
- Продуктовые логи в PostgreSQL (`processing_logs`, `intake_events`), технические — SQLite.

---

## 4. Нефункциональные требования

- Production-ориентированность: multi-stage Docker-образы, health-статусы в compose, идемпотентные миграции.
- Ресурсный контур: работа на VPS 7.8 GiB RAM; heavy-RAG safeguards (лимиты upload, защищённые пробы с таймаутами, закрытие клиентов).
- Воспроизводимость: `.env.example` с плейсхолдерами, RUNBOOK как SOT развёртывания.

---

## 5. Вне скоупа текущей версии

- Multi-tenant изоляция, external IAM/OAuth (Keycloak — направление P9.7).
- Отдельный контейнер-воркер (воркер — поток внутри admin-api), CI/CD, автоматические бэкапы, S3 object storage.
- Semantic/glossary-aware chunking (P5.5).

---

## 6. Критерии приёмки

- Развёртывание с нуля по RUNBOOK в чистом окружении (Deployment Validation).
- Smoke: health, Telegram `/start`, загрузка документа + RAG-запрос с источниками, вход в консоль по токену и демо-входом, журнал аудита фиксирует обращения.
- Демо-сценарии из [DEMO_SCENARIOS.md](DEMO_SCENARIOS.md) проходят на живом инстансе.
